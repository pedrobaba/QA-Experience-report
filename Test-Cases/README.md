# Test Cases

This section contains structured test cases and test scenarios created to demonstrate my practical approach to software testing.

The test cases in this portfolio are designed around functional and content validation scenarios commonly encountered during web and mobile application testing.

## Purpose

These test cases demonstrate my ability to:

- Analyze application requirements and expected behaviour
- Identify positive and negative test scenarios
- Define preconditions and test data
- Write clear and reproducible test steps
- Define expected results
- Execute and document test outcomes
- Identify functional and content-related defects

## Test Case Categories

### Functional Testing

Functional test cases verify that an application behaves according to its expected requirements.

Examples include:

- User authentication
- Search functionality
- Form validation
- Navigation
- Buttons and links
- Product interactions
- Error handling

### Content Testing

Content testing focuses on verifying that information displayed to users is accurate, complete and correctly presented.

Examples include:

- Text and labels
- URLs and links
- Dates and times
- Spelling and grammar
- Error messages
- Product information
- Page content consistency

### Exploratory Testing

Exploratory testing is documented separately using test charters and session notes rather than relying only on predefined test cases.

This demonstrates my ability to investigate an application, learn its behaviour, design tests dynamically and identify unexpected issues.

## Confidentiality

Test cases based on crowdtesting experience are anonymized where necessary. No confidential client information, private URLs, credentials, restricted screenshots or sensitive test-cycle information is included in this repository.

## Test Case Format

Each test case may include:

- Test Case ID
- Title
- Test Type
- Priority
- Preconditions
- Test Data
- Test Steps
- Expected Result
- Actual Result
- Status
- Notes or Evidence
